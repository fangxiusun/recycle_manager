# 已知问题

这里只收「用起来会撞到」的限制及其原因；每条都能在
[构建与验证](构建与验证.md)、[图形界面使用与解析](图形界面使用与解析.md) 或源码里找到对应记录。

## 数据安全

- **删除是永久的**：直接抹掉 `$R` 数据与 `$I` 元数据，不经过回收站，删了就没了。
  三道闸门是叠加的：【预览删除】/ `--dry-run`（默认，不动文件）→ 确认框（报本次规模与分区编号）→
  「删除保险丝」/ `--max N`（选中条目数超过 N 就整批拒绝，连账本文件都不打开）。
- **重新扫描会重新编号**：分区编号只在当前快照内有效，已删完的条目不会再出现在新快照里。
  回收站很大时优先用 `shell`：扫一次后复用内存里的快照，编号不会在你逐个删除的过程中漂移。
- **单次扫描默认最多 5 万条**（`--max-scan`），超限时只取最老的那些建快照，同时打印
  「共多少、取了多少、各盘已扫/总数、两条继续办法」，不会静默丢弃；`--max-scan 0` 为不限。
- **打开 GUI 会覆盖快照目录**（默认 `<cwd>\.rbm`）里的 `state.json` 与 `scan_list.csv`。
  需要留档先在【▼ 高级参数】里把快照目录指到别处。
- **勾选会被视图变化清掉**：切「只看未删完」会清空勾选（视图变了，留着旧勾选就会删错批）；
  点表头排序不清勾选。

## 采集范围

- 只看**当前用户 SID** 名下的 `$Recycle.Bin\<SID>`，不处理别的 SID 目录，也不处理缺 `$I` 的孤儿 `$R`
  ——这类进异常记录点名，本次不动。想管别人的回收站，就用那个用户登录再跑。
- 盘符来自 `GetLogicalDrives` 的 A–Z 掩码，`--drives` 只接受真实存在的盘符字母；
  网络盘、SUBST、被隐藏的卷不在处理范围。
- **时间分区按本机时区渲染**，Go 侧用的是启动那一刻的固定偏移：跨夏令时的历史条目会被按今天的偏移
  解释。中国大陆无夏令时，其他国家或地区的机器上注意这一条。

## 语言

- 只有中文和英文两种，中文是默认。
- 切语言只换「从这里开始」的文字，日志区已经写下的那几行保持写下时的语言。
- 落盘的内容不跟着语言走：`state.json` 的字段名与取值、两个 CSV 的中文表头、账本「结果」的「已删」、
  分组标签（「全部」「其他」「元数据损坏」「特殊位置」「(根)」「(无扩展名)」）、
  记录的断点规格 `gap:自动断点(<= N 桶)`。这是有意的——换标签会让磁盘上已有的快照和对参考实现的
  逐字节比对失效，见[构建与验证](构建与验证.md) §5.6。
- `docs/` 下的详解文档目前是中文。

## 发布与验证

- **未做代码签名**：首次运行 SmartScreen 可能提示「未知发布者」。按
  [构建与验证](构建与验证.md) §4 的哈希复核确认是官方产物再放行。
- **发布物的小瑕疵**：`rbm-${VER}-sha256.txt` 里两行 exe 的文件名带 `dist/` 前缀，而 zip 成员名不带——
  比对时按哈希值对齐，别按名字。
- CI 只做到字节层校验（PE 头、Subsystem、内嵌 manifest），**「双击下载包里的 `rbm-gui.exe` 真能开界面」
  还没有人工验证记录**。
- 表格重绘那一类 Win32 绘制行为**没有自动化回归用例**（测试不建窗口），修好的是
  2026-10-17 那一份产物的实测结果，见[图形界面使用与解析](图形界面使用与解析.md) §9。

## 平台

- 只有 Windows x86_64：`internal/gui` 依赖 `lxn/walk` 与 `golang.org/x/sys/windows`，
  这些文件带 `//go:build windows`，整个包在 Linux、macOS 上编译不过。
- 产物里没有安装程序，解压即用；配置和快照都在 `<cwd>\.rbm` 或你指定的快照目录、
  以及 `%LOCALAPPDATA%\rbm\settings.json`。
